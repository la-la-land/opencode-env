# Skill: browser-automation

Автономная проверка UI/JS через реальный браузер. Два MCP-сервера подключены:

- `chrome-devtools` — Google Chrome DevTools Protocol (chrome-devtools-mcp)
- `playwright` — Playwright MCP (@playwright/mcp)

Оба в headless + isolated по умолчанию (без дисплея, без shared state).

---

## 0. Триггеры загрузки

Грузится автоматически если в задаче есть:

- «проверь в браузере», «открой страницу», «кликни», «сделай скриншот»
- «работает ли», «баг в UI», «покажи что видишь», «прокликай flow»
- Любая frontend-задача где нужен реальный браузер для верификации
- После фикса во фронтенд-секциях проекта (JS-редакторы, шаблоны, страницы) — чтобы убедиться, что не сломал

---

## 1. Какой MCP выбрать

| Задача | Сервер |
|---|---|
| **Простое** — открыть страницу, кликнуть, прочитать console.log, сделать скриншот | **`playwright`** (быстрее, стабильнее refs) |
| **Глубокая отладка** — network HAR, performance trace, source-mapped stack traces | **`chrome-devtools`** |
| **Файл-аплоад** (input type=file) | оба умеют, `playwright.upload_file` проще |
| **iFrame / Shadow DOM** (сложные редакторы в Shadow DOM) | **`chrome-devtools`** — CDP-уровень лучше работает с shadow root |

---

## 2. Какие действия брать

- `browser.tabs.open` / `navigate` — открытие URL
- `page.content` / `page.text` / `page.screenshot` — что видит пользователь
- `page.query` / `page.click` — взаимодействие
- `page.console` — ошибки JS (всегда проверяй после загрузки страницы)
- `network` HAR / requests — что реально уходит на сервер

---

## 3. Порядок авто-проверки

1. Открой страницу (возьми URL из задачи/репозитория).
2. Дождись загрузки (не мгновенно — подожди ответа сервера).
3. Прочитай `console` — нет ли 4xx/5xx, JS-ошибок, timeout'ов.
4. Прокликай целевой flow.
5. Скриншот — приложи в отчёт.
6. Доложи: что увидел, какие ошибки, что работает.

---

## 4. Правила

- Не открывай посторонние сайты вне задачи.
- Скриншоты сохраняй в каталог проекта (`screenshots/`) — приложи ссылки.
- Не «щёлкай вслепую»: сначала прочитай DOM (`page.query` / текст), потом действуй.
- Consume «собственные» ресурсы: не дёргай внешние сети без нужды.
